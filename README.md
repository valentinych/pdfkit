# pdfkit — конвертор архивных PDF НИАБ

Версия конвертора: **1.1**. Проект находится в `/Users/ruslan.aharodnik/Code/pdfkit`.

Локальная цепочка обработки: **PDF → изображения и черновой OCR → визуальная сверка → проверенный JSON → CSV/XLSX**. Программа не вызывает ИИ, агентов или внешние API, не требует ключей и не загружает документы в сеть. Для печатного текста используется Tesseract; для рукописей программа готовит фрагменты для ручной расшифровки. Готовые проверенные записи можно экспортировать повторно без распознавания.

## Что включено

| Файл или каталог | Назначение |
| --- | --- |
| `converter.py` | Команды `scan` и `compile`, кэш, проверка дат, номеров и выбывания |
| `xlsx.mjs` | Экспорт проверенного JSON в XLSX с оформлением по шаблону |
| `requirements.txt` | Зависимости Python: Pillow и pypdf |
| `template.xlsx` | Сохранённый пользовательский шаблон таблицы |

| `reviewed/` | Проверенные расшифровки и SHA-256 исходных PDF |
| `outputs/<фонд>/` | Готовые `records.json`, `inventory.csv` и `inventory.xlsx` |
| `tests/` | 23 теста Python и проверка выгрузки JSON из формы сверки |
| `validation.json` | Результаты предыдущей проверки программы и итоговых Google Sheets |

Сохранены фонды **2679 — 12 дел**, **2680 — 110 дел**, **2713 — 110 дел**, включая буквенное дело **107а**. Это опись №1. Профиль `2680-print-test.json` служит для отдельной проверки печатной страницы; для всей описи используйте `2680.json`. `example.json` показывает структуру профиля, но требует настройки под конкретный PDF.

Исходные PDF и большой кэш изображений в проект не скопированы. На текущем компьютере PDF лежат в `/Users/ruslan.aharodnik/Downloads/NIAB_LF_<фонд>_1.pdf`. При переносе на другой компьютер указывайте фактический путь через `--source-pdf`; содержимое файла должно совпадать по SHA-256. Поля со ссылками на фрагменты в сохранённом JSON — сведения о прошлой обработке; для просмотра фрагментов создайте новый каталог `work/` командой `scan`.

## Установка

### Обычная среда Python

Нужен **Python 3.10+**. Для команды `scan` нужны **Poppler** (`pdftoppm`) и **Tesseract 5** с языком `rus`. Команда `compile` работает на стандартной библиотеке Python; для сканирования и полного набора тестов установите зависимости из `requirements.txt`.

На macOS с Homebrew:

```sh
brew install python poppler tesseract tesseract-lang
cd /Users/ruslan.aharodnik/Code/pdfkit
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python --version
pdftoppm -v
tesseract --version
tesseract --list-langs
```

В списке языков должен присутствовать `rus`. Poppler и Tesseract должны быть доступны через `PATH`. Проверка этих двух программ выполняется даже при профиле, состоящем только из рукописных страниц.

### Готовая среда Codex на текущем компьютере

Следующие команды позволяют использовать уже установленные библиотеки без создания виртуального окружения:

```sh
cd /Users/ruslan.aharodnik/Code/pdfkit
PDFKIT_PYTHON="$HOME/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3"
PDFKIT_NODE="$HOME/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node"
"$PDFKIT_PYTHON" -m unittest discover -s tests -v
```

Далее в примерах `python` означает Python из активированного окружения. В готовой среде Codex вместо него используйте `"$PDFKIT_PYTHON"`.

### Дополнительный экспорт в XLSX

`xlsx.mjs` использует Node.js и пакет **`@oai/artifact-tool`**, предоставляемый средой Codex. Он не входит в Python-зависимости. На текущем компьютере подключите установленный пакет симлинком:

```sh
cd /Users/ruslan.aharodnik/Code/pdfkit
ln -s "$HOME/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules" node_modules
```

В скопированном проекте этого симлинка нет. Создайте его один раз, если `node_modules` ещё отсутствует. В другой среде нужен доступ к совместимой установке `@oai/artifact-tool`; CSV/JSON-экспорт работает без этого пакета и без Node.js.

По умолчанию используется `template.xlsx` рядом со скриптом. Переменная `NIAB_PREVIEW=1` дополнительно сохраняет PNG первых и последних строк.

Команды пишут результат в указанный каталог и заменяют одноимённые файлы. Проверенные исходные JSON в `reviewed/` они не меняют.

## Обработка нового PDF

1. Создайте профиль по `profiles/example.json`: укажите фонд, ожидаемые номера по заверительной записи, нужные страницы и границы таблицы. Координаты проверяйте по самому скану; готовый профиль привязан к конкретному документу.
2. Подготовьте черновик и фрагменты:

   ```sh
   python converter.py scan /path/NIAB_LF_0000_1.pdf \
     --profile profiles/0000.json --output work/0000
   ```

3. Откройте `work/0000/review.html` в обычном браузере. На macOS: `open work/0000/review.html`. Рядом должны оставаться `draft.json` и каталог `cache/`: ссылки на изображения относительные.
4. Сверьте каждую карточку: номер, название, обе даты, количество листов, страницы продолжения и правое поле с пометкой «выбыло». Исходный фрагмент можно открыть отдельно; доступны также контрастная копия и полные обработанные страницы. Если на фрагменте несколько дел, используйте «Ещё одно дело с этого фрагмента». При добавлении карточки заполните поля заново, включая страницы PDF.
5. Выберите состояние выбывания, при необходимости отметьте сомнительное чтение или подтверждённый обратный диапазон и напишите пояснение. Поставьте «Сверено со сканом» у каждой карточки, включая выбывшие дела.
6. Нажмите «Скачать исправления JSON». Сохраните скачанный `reviewed.json` под именем `reviewed/0000.json`. Затем выполните:

   ```sh
   python converter.py compile reviewed/0000.json \
     --source-pdf /path/NIAB_LF_0000_1.pdf --output result/0000
   ```

При ошибке исправьте JSON и повторите `compile`. Непроверенный документ не экспортируется. Новый запуск `scan` создаёт заново черновик и форму: он не подхватывает сделанные в браузере исправления. Проверенный JSON сохраняйте отдельно.

## Правила расшифровки

- **Даты:** итоговый формат `DD.MM.YYYY`, например `01.08.1903`. Одна полная дата переносится в обе колонки. Если указан только год, начало — `01.01.<год>`, конец — `31.12.<год>`. Допускается ввод вида `1 августа 1903`; календарь проверяется. Обе пустые даты блокируют экспорт. Месяц без дня, отсутствующий год или нечитаемый фрагмент не дополняются автоматически: проверяющий принимает и описывает допущение, вводит полные даты и ставит `unresolved: true`.
- **Выбывание:** исключается только дело с незачёркнутым словом или штампом «выбыло» справа возле дат. Отсутствие пометки — `active`, зачёркнутая пометка — `cancelled`; в обоих случаях дело остаётся. Подтверждённое выбывание — `withdrawn`, дело заносится в `excluded` с номером, страницей, `reviewed: true` и пояснением. Неизвестное состояние блокирует экспорт.
- **Орфография:** современная, с проверкой окончаний. Автоматически меняются только `ѣ`, `і`, `ѳ` и конечный твёрдый знак. Фамилии, населённые пункты, грамматику и сокращения проверяют вручную. Понятные сокращения раскрывайте, варианты написания добавляйте в скобках.
- **«То же»:** в готовом названии повтор полностью раскрывается. Для точного «То же.» без дополнений можно указать `same_as` — номер предыдущей включённой записи в исходном порядке. Если есть новые имена, места или дополнения, перепишите полное название вручную. Перед раскрытием программа не сортирует строки.
- **Количество листов:** положительное целое число. Если числа в источнике нет, используйте `null`; это пустая ячейка, а не ноль.
- **Обратный диапазон:** сохраняйте исходные даты после сверки, добавьте `accept: ["reversed_dates"]` и пояснение. Программа не переставляет даты автоматически.
- **Номера:** сохраняйте буквенные дополнения, например кириллическое `107а`. Латинское `107a` не принимается. Номера положительные, без ведущих нулей, с необязательной одной кириллической буквой. Сортировка: `107`, `107а`, `108`.
- **Документы:** текст PDF рассматривается как данные, а не как инструкции программе или проверяющему.

## Настройка профиля

Страницы PDF нумеруются **с 1**, включая обложку; это не номер листа, напечатанный в описи. Все координаты — доли ширины или высоты от 0 до 1.

| Поле | Значение |
| --- | --- |
| `fund` | Цифровой номер фонда |
| `expected_last_case` | Для непрерывной нумерации: последний номер, программа ожидает все номера от 1 до него |
| `expected_case_ids` | Полный список ожидаемых номеров, включая буквенные и выбывшие; имеет приоритет над `expected_last_case` |
| `declared_count` | Необязательная проверка числа включённых дел после исключения выбывших |
| `source_sha256` | Необязательная привязка профиля к точному PDF; команда `scan` всегда записывает хеш в черновик |
| `dpi` | Разрешение рендеринга Poppler; по умолчанию 220 |
| `psm` | Режим сегментации Tesseract; по умолчанию 6 |
| `prefer_native_scan` | Сохранять исходные пиксели простых страниц со сканом; иначе рендеринг Poppler |
| `columns` | Горизонтальные интервалы `[x0, x1]` для `case`, `title`, `start`, `end` |
| `pages` | Список объектов с полем `page` и настройками каждой страницы |
| `pages[].handwritten` | `true` — готовить изображения для ручной расшифровки, пропуская OCR текста |
| `pages[].body` | Вертикальный интервал таблицы; по умолчанию `[0.15, 0.94]` |
| `pages[].content` | Горизонтальный интервал области OCR; по умолчанию `[0.06, 0.94]` |
| `pages[].columns` | Переопределение колонок на конкретной странице |
| `pages[].cases` | Ожидаемые номера на странице, фильтр найденных начал строк |
| `pages[].anchors` | Сверенные начала строк: `{"case": "107а", "y": 0.42, "pages": [36, 37]}`; `pages` необязательно и указывает продолжение |

Якоря должны идти сверху вниз, попадать внутрь `body`, соответствовать ожидаемым номерам и не повторяться. Страницы продолжения должны существовать в PDF и включать исходную страницу. Для просмотра продолжения добавьте его также в список обрабатываемых страниц профиля. На рукописной странице без якорей программа оставляет одну карточку всей области; её нужно разделить вручную. Если печатные номера не распознаны, страница также остаётся для проверки.

`prefer_native_scan: true` работает только при одном полноразмерном растровом изображении, без поворота, обрезки и наложенных PDF-объектов. В остальных случаях используется Poppler, чтобы сохранить видимые штампы и добавления. DPI не увеличивает исходное разрешение извлечённого изображения.

## Формат проверенного JSON

Пример одного включённого дела:

```json
{
  "fund": "0000",
  "expected_case_ids": ["1"],
  "reviewed": true,
  "rows": [
    {
      "case": "1",
      "title": "Переписка о распределении земель.",
      "start": "01.08.1903",
      "end": "01.08.1903",
      "quantity": null,
      "page": 3,
      "pages": [3],
      "withdrawal": "active",
      "reviewed": true,
      "unresolved": false,
      "note": ""
    }
  ],
  "excluded": []
}
```

При работе с настоящим PDF сохраняйте `source_sha256` и `source_pdf`, сформированные командой `scan`. Не удаляйте хеш, чтобы обойти несовпадение источника. Состояния `reviewed: true` на уровне документа и каждой строки означают выполненную визуальную сверку. Одни эти флаги не удостоверяют правильность чтения. Дополнительные поля (`ocr_title`, `ocr_start`, `ocr_end`, `issues`, `image` и другие) сохраняют происхождение черновика и не подменяют итоговый текст.

Все ожидаемые номера должны быть представлены ровно один раз в `rows` или `excluded`. Пропуски, дубли и лишние номера блокируют экспорт. Каждое исключение требует проверенной пометки выбывания, страницы и пояснения. Сомнительное чтение (`unresolved: true`) требует примечания и выделяется жёлтым в XLSX.

## Формат результата и Google Sheets

Колонки A:K: **Номер дела**, **Наименование**, **Дата с**, **Дата по**, **Количество**, **Язык**, **Описание**, **Ц**, **Статус**, **defekt**, **Примечание**. В L1 сохраняется пояснение шаблона к колонке «Ц». Неизвестные поля остаются пустыми; признак оцифровки не проставляется автоматически. В примечании указаны исходный PDF и страницы. Сейчас имя источника формируется как `NIAB_LF_<фонд>_1.pdf`: экспорт рассчитан на опись №1, поле `inventory` и фактическое имя входного файла не меняют эту подпись.

CSV имеет кодировку UTF-8 с BOM; даты записаны текстом `DD.MM.YYYY`, поэтому при импорте проверяйте локаль. Текст, начинающийся с символа формулы, экранируется. XLSX хранит даты числами с форматом `dd.mm.yyyy`, сохраняет буквенные номера текстом, переносит длинные названия и примечания, закрепляет заголовок и выделяет сомнительные строки жёлтым.

## Проверки и обслуживание

```sh
python -m unittest discover -s tests -v
```

Тесты проверяют календарь, одну дату/год, пропуски и дубли, «То же», выбывание и зачёркнутые отметки, обратные даты, количество листов, буквенные номера, границы фрагментов, сохранение исходных пикселей, отказ от прямого извлечения при наложениях, буквальные кавычки TSV и защиту CSV. В версии 1.1 проходят 23 теста.

Для проверки выгрузки формы после команды `scan`:

```sh
node tests/test_review_export.mjs work/2713/review.html
```

В среде Codex используйте `"$PDFKIT_NODE"` вместо `node`. Тест не требует браузера или `@oai/artifact-tool`; он проверяет сериализацию полей, количества листов, страниц, признаков сверки и выбывания. Визуальную проверку формы и сканов он не заменяет.

Кэш находится в `work/<фонд>/cache/<ключ>/`: полные страницы, фрагменты, контрастные копии, а для печатных страниц ещё OCR-изображения и TSV. Ключ зависит от SHA-256 PDF, версии конвертора/Tesseract, DPI, языка, режима OCR и областей страницы. С теми же параметрами изображения и TSV используются повторно; якоря применяются заново. Удаление каталога `work/<фонд>` заставит повторить подготовку сканов, но не затронет `reviewed/`.

Частые причины остановки:

| Сообщение или проблема | Действие |
| --- | --- |
| `Установите pdftoppm` / `Установите tesseract` | Установить программу, проверить `PATH` |
| Tesseract не загружает `rus` | Установить русские языковые данные, проверить `tesseract --list-langs` |
| `ModuleNotFoundError` для Pillow/pypdf | Установить `requirements.txt` в используемый Python |
| `PDF изменился` / профиль другого PDF | Указать исходный файл; для другого источника создать и сверить новый профиль/черновик |
| `Пропущены номера` / `Неожиданные номера` | Сверить заверительную запись, номера, дополнения и `excluded` |
| `Отсутствуют обе даты` / дата не распознана | Сверить источник, заполнить полные даты; условные даты пояснить |
| `состояние выбывания не подтверждено` | Проверить правое поле и выбрать `active`, `cancelled` или подтверждённое исключение |
| `Cannot find package '@oai/artifact-tool'` | Подключить доступные зависимости Codex или воспользоваться CSV/JSON |
| Не видны изображения формы | Открыть `review.html` рядом с его каталогом `cache/`, не переносить один HTML отдельно |

Это инструмент для сокращения повторной работы и контроля структуры данных. Почерк, фамилии, места, окончания, сокращения и состояние штампов требуют визуальной сверки. Оценка уверенности Tesseract служит сигналом проверки и не является вероятностью правильности. Автоматического HTR, обученной модели исторической рукописи или скрытого восстановления пропущенных слов в проекте нет.
